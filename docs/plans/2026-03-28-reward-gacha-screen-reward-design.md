# 리워드 가챠 화면 + 보상 구조 디자인

## 문서 범위

이 문서는 사용자와 합의된 **가챠 화면 디자인**과 **보상 구조**만 정리한다.
확률 상세값, 포인트 경제 수치, 구현 계획, DB 설계 확정안은 아직 포함하지 않는다.

## 전제

- 기존 프로젝트의 **디자인 토큰을 그대로 사용**한다.
- 화면 톤은 **밝은 러닝앱형**을 유지한다.
- 가챠 감정은 과한 신규 비주얼 시스템이 아니라 **카드 뒤집기 인터랙션**에서 만든다.

### 스타일 참조 기준

구현 또는 시안 구체화 시 아래 파일을 반드시 참고한다.

- `web/src/shared/styles/index.css`
- `web/src/shared/styles/shadcn.css`
- `web/src/shared/styles/tokens/color.css`
- `web/src/shared/styles/tokens/spacing.css`
- `web/src/shared/styles/tokens/typography.css`
- `web/src/shared/styles/tokens/radius.css`
- `web/src/shared/styles/tokens/shadow.css`

규칙:

- **raw hex/RGB 값을 직접 추가하지 않는다.**
- 색상은 `color.css`의 semantic HSL 토큰을 기준으로 잡는다.
- 간격은 `spacing.css` 토큰을 기준으로 잡는다.
- 전체 UI 연결은 `index.css`와 `shadcn.css`의 기존 브리지 방식을 따른다.

## 가챠 상품 구조

- 가챠 상품은 여러 개가 아니라 **단일 가챠 1개**다.
- 가격은 **포인트 1개 고정 가격**으로 운영한다.
- 사용자는 여러 상품 중 하나를 고르는 것이 아니라, 하나의 가챠를 실행한다.

## 화면 구조

첫 화면은 아래 흐름으로 구성한다.

1. **포인트 표시부 + 인벤토리 버튼**
   - 포인트는 정보 카드보다 **기계판 같은 긴장감 있는 표시형**으로 보인다.
   - 인벤토리 버튼은 포인트 영역 옆의 **조용한 보조 버튼**으로 둔다.

2. **중앙 카드 스테이지**
   - 화면의 중심은 보상 배너가 아니라 **미스터리 카드팩**이다.
   - 이 카드팩이 실제 가챠의 메인 오브젝트가 된다.

3. **큰 `뽑기 시작` 버튼**
   - 반짝이는 핵심 CTA로 배치한다.
   - 메인 화면의 가장 강한 액션 요소다.

4. **카드 중심 레이아웃**
   - 대표 보상 카드나 별도 보상 전시를 전면에 두지 않는다.
   - 메인 화면은 카드팩과 카드 결과 중심으로 단순하게 구성한다.

## 결과 연출 구조

- 결과는 풀스크린 팝업이 아니라 **카드 뒤집기형**으로 진행한다.
- 사용자는 현재 화면 위에서 카드를 직접 뒤집으며 결과를 확인한다.
- `뽑기 시작`을 누르면 버튼은 사라지고, 포인트 영역은 **살짝 흐려지며 뒤로 물러난다.**
- 그 다음 화면 중심이 카드팩으로 이동하고, 카드팩은 **터지듯 오픈**된다.

### 카드 수 규칙

- 카드 개수는 **처음부터 확정되어 한 번에 보인다.**
- 카드는 **가로 일렬 정렬**로 등장한다.
- 모든 카드는 **같은 크기와 같은 비중**으로 노출된다.
- 카드 앞면에는 **아무 정보도 없다.**
- 사용자는 **원하는 카드부터 직접 선택**해 뒤집는다.
- 한 번 열린 카드는 **열린 상태 그대로 유지**된다.

즉, 사용자는 카드팩이 열린 직후 이번 판의 카드 수를 한 번에 인지하고,
그다음부터는 순전히 자기 선택으로 카드를 열게 된다.

### 카드 공개 방식

- **꽝 카드**는 처음에는 빈 카드처럼 보였다가, 이후 꽝으로 확정된다.
- **당첨 카드**도 처음에는 빈 카드처럼 보였다가, **빛 반짝임 후 아이템이 공개**된다.
- 꽝과 당첨은 첫 순간이 비슷하게 출발하고, 마지막 연출에서 갈리게 한다.

### 결과 종료 방식

- 별도의 결과 요약 바는 두지 않는다.
- **열린 카드들의 상태 자체가 최종 결과 화면**이 된다.
- `닫기` 버튼은 **모든 카드를 연 뒤에만** 나타난다.
- `닫기` 버튼 위치는 **카드 스테이지 바로 아래**다.
- `닫기`를 누르면 같은 가챠 메인 화면으로 돌아가되, **화면은 완전히 초기화**된다.

## 보상 구조

한 번의 가챠에서 카드 여러 장이 뜰 수 있고,
카드를 뒤집어 **복수 아이템을 획득할 수도 있다**.

보상 계층은 다음과 같다.

1. **상위 보상**
   - 스타벅스 기프티콘
   - 배달의민족 상품권

2. **중간 보상**
   - 소액 커피 쿠폰
   - 배달비 할인권
   - 소액 금액권

- 실제 노출되는 보상 아이템 메타데이터는 프론트 하드코딩이 아니라 **백엔드 보상 아이템 테이블**을 기준으로 관리한다.
- 보상 아이템 테이블의 최소 필드는 `title`, `imageUrl`로 둔다.

3. **꽝**
   - 실제로 포함된다.
   - 체감상 **꽝이 많은 구조**를 전제로 한다.

## 재도전권에 대한 현재 방향

- 재도전권은 기본 보상이 아니라 **희귀 보너스성 결과**로 본다.
- 다만 이 문서 범위에서는 확정 보상풀로 완전히 잠그지 않고,
  추후 확률/경제 설계 때 최종 반영 여부를 다시 확인한다.

## 감정 설계

이 화면의 첫 감정은 **긴장감**이다.
그 긴장감의 원천은 꽝 공포보다 **상위 보상 희소성**에 더 가깝다.

핵심 감정은 아래 흐름으로 설계한다.

- 시작 전: “이번에 희귀한 게 나올까?”
- 버튼 직후: “이제 곧 열린다.”
- 카드 등장 후: “어느 카드를 먼저 열지?”
- 공개 순간: “빈 카드인가, 당첨인가?”

즉, 이 UX의 중심은 상품 선택이 아니라 **카드팩 개봉과 카드 선택의 긴장감**이다.

## 인벤토리 구조

- 메인 화면의 포인트 영역 옆에 인벤토리 버튼이 있다.
- 인벤토리에는 **꽝을 제외한 아이템만** 보여준다.
- 정렬 기준은 **최신 획득순**이다.
- 배치는 **가로 슬라이드**다.
- 각 아이템은 **이미지 중심**으로 노출한다.
- 인벤토리와 가챠 결과에 쓰이는 아이템 정보는 백엔드 API 가 내려주는 `title`, `imageUrl` 기준으로 맞춘다.
- 이미지를 누르면 상세 정보 대신 **큰 이미지 보기만** 제공한다.

## 아직 미확정인 항목

다음은 후속 논의가 더 필요하다.

- 포인트 적립/소모 수치
- 카드 추가 생성 확률
- 상위/중간/꽝의 상세 확률
- 재도전권의 최종 포함 여부와 위치
- 일일 제한 / 재고 정책
- 가챠 실행 / 포인트 / 인벤토리 API 세부 계약
- 구현 범위와 우선순위

## 현재 합의 요약

- 기존 디자인 토큰 사용
- 밝은 러닝앱형 톤 유지
- 단일 가챠 상품 1개
- 가격 1개 고정
- 포인트 영역은 기계판 같은 긴장감 있는 표시형
- 인벤토리 버튼은 포인트 영역 옆의 조용한 보조 버튼
- 중심 오브젝트는 미스터리 카드팩
- CTA는 반짝이는 `뽑기 시작` 버튼
- 버튼을 누르면 CTA는 사라지고 포인트 영역은 흐려지며 뒤로 물러남
- 결과는 카드 뒤집기형
- 카드팩은 터지듯 오픈
- 카드는 처음부터 개수가 확정되어 한 번에 보임
- 카드들은 가로 일렬 정렬
- 모든 카드는 같은 크기/비중이며 앞면 정보가 없음
- 사용자가 원하는 카드부터 직접 선택해 오픈
- 카드 여러 장에서 복수 아이템 획득 가능
- 꽝 포함
- 꽝이 많은 구조
- 꽝은 빈 카드처럼 보였다가 확정
- 당첨은 빈 카드처럼 보였다가 빛 반짝임 후 공개
- 열린 카드는 열린 상태 그대로 유지
- 결과 요약 없이 카드 상태 자체가 최종 결과
- 모든 카드를 연 뒤에만 닫기 버튼 노출
- 닫기 위치는 카드 스테이지 바로 아래
- 닫기 후 메인 화면 완전 초기화
- 인벤토리에는 꽝 제외 아이템만, 등급 높은 순, 가로 슬라이드, 이미지 확대만 제공
